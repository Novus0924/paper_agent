## 2. 我要交付什么（后端范围）

按需求文档 §3.2 架构图，"后端"不只是一个 HTTP 服务，而是三层：

```
① BFF（新建，Node 24 + TypeScript）
   ├─ REST API（/api/health + /api/v1/tasks 系列）
   ├─ SSE 事件推送
   ├─ 应用服务：任务/执行/消息/报告/证据/导出
   ├─ 读模型（面向视图 DTO，用户字段与审计字段分离）
   └─ Session Gateway：经 @agnes/sdk 驱动 AGH 会话 —— 唯一执行出口
② 领域层
   ├─ AGH 插件：sciret_* 工具（薄壳，注册进 AGH）
   └─ Python 确定性内核（状态机/证据账本/流水线/报告装配，零第三方依赖、纯标准库、可复现）
③ 运维层
   ├─ 一键启动器（编排 AGH daemon + BFF + 前端，健康等待后开浏览器）
   └─ doctor 环境自检（Node≥24 / Python≥3.10 / 端口 / 插件信任 / 模型配置 / 连通性，含人类可读修复指引）
```

**三条技术红线（不可违背）：**
1. 领域确定性内核：Python 标准库、零第三方依赖、可复现；
2. **执行不得绕过 AGH**（最高优先级架构约束）——BFF 禁止直接 spawn Python 跑主链路；
3. BFF 技术栈与 AGH 同生态：Node 24 + TypeScript，使用官方 `@agnes/sdk`。

**明确不做（Out of Scope）**：多用户/鉴权（仅预留可选 token 开关）、云部署、论文全文批量抓取、用 LLM 自由编排取代确定性状态机、跨 run 数据库查询层。

## 3. 核心架构理解（一句话 + 数据流）

**一句话**：BFF 只做编排与读模型，不重造底座——AGH 提供"运行时 + 记忆 + 导出"，Python 内核提供"确定性流水线"，报告是聚合根与统一交付物。

**写路径（执行流）**：
前端操作 → BFF 应用服务 → Session Gateway（@agnes/sdk）→ **AGH 会话**（全程留痕）→ sciret_* 插件工具 → Python 内核 → `runs/` 产物落盘（原子写）。

**读路径（回流）**：
内核产物 → AGH 会话事件 + BFF 读产物 → Event Relay 归一化 → SSE / 报告 DTO → 前端。

**关键机制**：
- **Task ↔ Session 1:1 映射**：创建任务时经会话网关建立 AGH 会话并持久保存 `session_id`；step/run-all/resume/message 全部作用于同一会话；BFF 重启后凭映射 reattach；映射存本地 JSON（结构对 SQLite 友好）。验收以 AGH `sessions` / `export` 可查到记录为准。
- **状态机**：Run `PLANNED→RUNNING→DONE|FAILED`；Step `PENDING→RUNNING→DONE|FAILED|SKIPPED`；全部 DONE/SKIPPED 自动收敛 DONE；终态幂等不可逆；终态产物损坏应新建 Task 而非回改。
- **三级降级语义**（P-01 核心）：L0 正常（覆盖达标，即使个别源不可用）；L1 信息（个别源不可用但覆盖充足，仅记录 source_status，`degraded=false`）；L2 真降级（路径实质改变：回落本地/跳步/OCR 低置信/覆盖不足，`degraded=true`）。用户主动选 local **不判降级**；chaos 故障注入默认关闭且 Fail-closed。
- **报告门禁**：生成前校验哈希链完整、结论 100% 绑定 fact 级证据、判断批次齐全；不通过则拒绝并给原因；报告 tmp + `os.replace` 原子写、幂等可重取。
- **SSE 三保证**：有序（单调序号）、幂等去重（step/cid/turn_id 稳定 ID）、可恢复（先注册订阅再直写快照——修复旧版竞态；支持 Last-Event-ID）；终态 `done` 帧必达（先写 socket 再清理资源）。

## 4. P-01 ~ P-07：七个旧问题与后端解法（验收靶心)

| 编号 | 旧问题 | 我的后端解法落点 |
|---|---|---|
| P-01 | 任务总是降级 | 三级降级语义 + 覆盖策略（≥2 源成功且命中数达标即成功）+ 连通性预检 Preflight + 指数退避重试（瞬时错误才重试、4xx 不重试）+ 多源受控并发按固定顺序归并 + chaos Fail-closed |
| P-02 | 前端暴露过多后端内容 | 分层 DTO/读模型：默认响应不含原始提示词/哈希；审计字段经显式参数或独立受控方式获取 |
| P-03 | 输出零散、未形成报告 | 报告聚合服务（结构化 + MD）+ 终态门禁 + 原子写 + 事件目录补全 + 终态必发 `done` + 报告可重取、未就绪返回 `{"status":"generating"}` |
| P-04 | AGH 中无记录、无法导出 | **所有执行经 AGH 会话驱动**（SDK/无头会话），禁止 BFF 直接 spawn；Task↔Session 1:1 持久映射；导出复用 AGH 原生 `export` |
| P-05 | 底部对话框不起作用 | 会话消息接口：同会话多轮 ask/revise；运行中排队、按序执行；返回消息与增量事件 |
| P-06 | 未真正继承 AGH | AGH = 运行时+记忆+导出底座；领域能力以 AGH 插件工具交付；BFF 只做编排与读模型；提供 AGH 集成一致性校验 |
| P-07 | 启动麻烦 | 一条命令启动（AGH→BFF→前端，健康等待，开浏览器）+ doctor 自检（含 `--json`/`--quiet`，退出码 0/2/1）+ 配置安全默认值 + 路径自动探测 |

## 5. 接口设计理解（严格按 §8，逐条落实）

统一约定：前缀 `/api/v1`（health 除外）；仅绑定 `127.0.0.1`；UTF-8 JSON；错误体统一 `{"error": string, "code": string}`；task_id 白名单 `^run-[0-9A-Za-z_-]+$` 防目录穿越。

### 5.1 接口总表（15 条，一个都不能少）

| # | 方法 | 路径 | 用途 | 要点 |
|---|---|---|---|---|
| 1 | GET | `/api/health` | 健康探针 | 版本、根、运行目录、任务数、会话/插件状态（无 v1 前缀） |
| 2 | GET | `/api/v1/tasks` | 任务列表 | 支持 `?status=` 过滤 |
| 3 | POST | `/api/v1/tasks` | 创建任务 | body: `goal`(必填,去空格非空,长度上限8192) / `workflow`(缺省 research) / `lit_source`(local\|arxiv\|auto) / `sources[]`；201 返回 `task_id` + `session_id` + `state` + `preflight`（各源 ok/unavailable:原因）；非法值回退默认并显式告知；400 `BAD_GOAL/BAD_BODY`；500 `SESSION_ERROR` |
| 4 | GET | `/api/v1/tasks/{id}` | 任务快照 | 面向视图 DTO（TaskSnapshot） |
| 5 | POST | `/api/v1/tasks/{id}/run-all` | 经会话跑完整流程 | 会话中产生完整工具调用序列；终态 DONE 且报告就绪 |
| 6 | POST | `/api/v1/tasks/{id}/step` | 经会话推进单步 | body: `step` |
| 7 | POST | `/api/v1/tasks/{id}/resume` | 断点续跑 | 已 DONE/SKIPPED 复用，仅跑 PENDING/FAILED |
| 8 | POST | `/api/v1/tasks/{id}/stop` | 请求停止 | 终态以实际为准 |
| 9 | GET | `/api/v1/tasks/{id}/events` | **SSE 实时事件** | 响应头 `text/event-stream`/`no-cache, no-transform`/`keep-alive`/`X-Accel-Buffering: no`；建连 `retry: 2000` → 注册订阅 → 直写快照 → 续实时；30s 心跳；并发触发另一请求得 409 `BUSY` |
| 10 | GET | `/api/v1/tasks/{id}/report` | 结构化报告 | 就绪 `200 {status:"ready", report:{title,abstract,sections,conclusions[]}}`；未就绪 `200 {status:"generating"}`（不报错）；404 任务不存在 |
| 11 | GET | `/api/v1/tasks/{id}/report.md` | 报告 Markdown | `text/markdown`；含结论证据角标与降级声明；`X-Content-Type-Options: nosniff` + `Content-Disposition: inline` |
| 12 | GET | `/api/v1/tasks/{id}/evidence` | 证据/结论/轨迹只读 | 面向视图 DTO |
| 13 | GET | `/api/v1/tasks/{id}/cite?ev=EV-0001` | 引用回查 | DOI/作者/年份或产物哈希前缀 |
| 14 | POST | `/api/v1/tasks/{id}/messages` | 多轮追问/修订 | body `{text, action: ask\|revise}`；空闲 `200 {queued:false, turn_id, status:"running"}`；运行中 `200 {queued:true, order:1}` |
| 15 | GET | `/api/v1/tasks/{id}/export?kind=report\|audit\|session` | 导出 | report→MD 文件流；audit→ZIP（报告+账本+事件+结论+校验脚本）；session→AGH 会话轨迹（经原生导出）；未完成 409 `NOT_READY` 并说明可导出范围 |

### 5.2 SSE 事件目录（9 种，§5.1）

`ping`（心跳）/ `step`（步骤状态）/ `activity`（人类可读过程描述）/ `tool`（工具调用，默认折叠供过程细节）/ `degraded`（level: info|degraded + source/reason/impact/resumable/step）/ `conclusion`（cid 去重补发）/ `message`（多轮增量）/ `report`（ready|generating）/ `done`（终态必达，含 run_status/report_ready/error?）。

### 5.3 错误码全集（§8.3）

`BAD_GOAL / BAD_BODY / BAD_PARAM / BAD_ID / NOT_FOUND / NO_REPORT / BUSY / BAD_STATE / NOT_READY / SESSION_ERROR / CLI_ERROR / EXPORT_ERROR`

### 5.4 状态与枚举（附录 A，权威、单一真源）

- RunStatus：`PLANNED / RUNNING / DONE / FAILED`
- StepStatus：`PENDING / RUNNING / DONE / FAILED / SKIPPED`
- Evidence.tier：`fact / artifact`（**只有 fact 可进结论**）
- Evidence.kind：`literature / data / analysis / note / factcheck / draft / review`（+实验类扩展）
- Degraded.level：`info / degraded`

> 前端文档附录 A 的 DTO 字段陷阱（tier 与 kind 不可混用等）已同步注意，契约以共享类型/OpenAPI 约束防漂移。
