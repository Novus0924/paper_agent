## 2. 缺口一：`workflow=materials` —— 失败点太晚

### 2.1 原状（两重问题）

```
POST /tasks {"workflow":"materials"}   → 200 建任务、开 AGH 会话
... 用户点运行 ...
第 1 步 P1 → PipelineError: 步骤 P1 尚未实现
```

**问题①（显性）**：失败发生在执行第 3 步。任务已建、AGH 会话已开、
真实模型回合已消耗，才告知选的工作流跑不通。

**问题②（隐性，更糟）**：对**完全未知**的工作流，`plan` 会**静默回退** research：

```python
wf = wf_raw if workflow.is_known(wf_raw) else workflow.DEFAULT_WORKFLOW
# 只在返回值里写一行 workflow_fallback
```

用户以为跑的是 materials，实际跑的是 research —— **产物结构与预期不符却毫无拦截**。
这是比"报错"坏得多的失败模式：**报错会让人停下，静默替换只会让人拿着错数据继续走。**

### 2.2 修复

**术语层面先拆开**（`kernel/sciret_kernel/workflow.py`）：

| 函数 | 含义 | materials |
|---|---|---|
| `is_known()` | 规格已定义 | ✅ true |
| `is_implemented()` | **算子齐备** | ❌ false |

只声明规格、不声明可执行性，混淆的正是问题根源。

**三道闸门**：
1. BFF `POST /tasks` 入口即 400，并给出可用替代（`WORKFLOWS_NOT_IMPLEMENTED` 说明文案）；
2. 内核 `plan` 阶段报错（省下"建目录 + 开 AGH 会话"的资源浪费）；
3. `execute_step` 兜底（历史任务/状态被外部改过时的最后一道）。

未知工作流改为**报错**，不再静默回退。

### 2.3 验证

```
materials → 400 + "…算子尚未实现。MVP 请用 workflow=research（多源检索→…→自评审）。"
未知      → 400 + "未知工作流：chemistry（可用：materials, research）。
                不再静默回退到 research —— 工作流决定步骤集与产物结构，跑错就是错的。"
research  → 200 + "workflow_fallback": null
```

**两侧口径由测试锁定**：`workflow-contract.test.ts` 新增用例断言
「API 接受集== 内核可执行集」。我第一版写成"不一致时打 warn"—— 那是**没有牙齿的测试**，
等于把关键不变量变成提醒，已改为硬断言（并因此真的抓到一次不一致：内核 `plan` 当时还收 materials）。

## 3. 缺口二：`lit_source=arxiv/auto` 从不联网

### 3.1 原状

`LIT_SOURCES = ['local','arxiv','auto']` 照收，但内核里
`corpus.select_snapshot()` 对三个值都落到**本地快照选优**。
真正联网的 `kernel/tools/fetch_corpus.py` **没有任何代码调用**（只被文档提到）。

数据本身是真实的（真 DOI，如 `10.1002/adfm.202211387`），所以 DoD 的"数据真实"成立——
但只有 6 条、不随时间更新。**若评委问"换个主题实时检索"，会露馅。**

### 3.2 修复（新增 `kernel/sciret_kernel/online.py`）

`arxiv`/`auto` → 真联网抓 Crossref/OpenAlex → 冻结成快照 → 走**原有确定性读取路径**。

**为什么在线检索要先冻结再读**，而不是让流水线直接联网：
项目红线是**可复现**。若流水线直接联网，同一目标两次执行会拿到不同文献
→ `ledger_digest` 变化 → 摘要不可复现。沿用既有约定（先冻结、再确定性读），
在线模式只是"读之前多一步刷新快照"。

**三条必须守住的约束**（都踩过）：

| 约束 | 不守会怎样 |
|---|---|
| 快照名由**目标哈希**派生，不含时间戳 | 同目标两次抓取产生不同文件名 → `corpus_snapshot` 抖动 → 违反可复现红线 |
| `local` **排除 `live-*`** | `live-*` 取决于抓取时刻；`local` 选中它就不再可复现，且用户选了离线却吃到联网结果 |
| 抓取失败**必须留痕** | 原因若被快照里的 `ok:N` 覆盖，"这次其实没联网"就从审计里消失了，§2.2 三级语义前提被破坏 |

### 3.3 降级语义

在线抓取失败 → 回落既有快照 → 记 **L1（info），不置 `degraded`**：
数据仍真实，只是时效性打折；置 `degraded` 会让用户以为结论不可信。

⚠️ 判定的优先级有个坑：若同时开了 chaos 演练，源不可用的原因是**注入**，
应按注入语义判定 —— 所以加了 `and not injections`。
不加的话演练结果会被"抓取失败"这条噪声覆盖，**三个降级用例全挂**（我确实踩了）。

### 3.4 实测验证

联网成功：
```
human_summary: 已检索 6 篇文献（语料快照 live-solid-state-...-e873c25b63f3；来源：crossref=ok:8, openalex=ok:8）
degraded: false      ← L0
```
离线回落：
```
human_summary: … 来源：crossref=ok:8, openalex=ok:8, __online_fetch__=fallback:已由 PAPER_AGENT_OFFLINE=1 强制离线）；
              ⚠️ 在线抓取失败已回落本地快照（…），元数据为历史版本
degraded: false      ← L1（info）
```

**两次失败才成功**：`No module named sciret_kernel` 连踩两次——
第一次以为设了 `cwd` 就够（不够，`cwd` 不会加进 `sys.path`）；
第二次设了 `PYTHONPATH` 但给了**包目录**（应该是它的父目录）。

## 4. 顺带修掉的一个真实回归

实现在线检索后，内核 `test_L0_all_sources_ok_no_degradation` 挂了：
`'ok:8' != 'ok:4'`。

根因：`available_snapshots()` 按文件名排序，新增的 `live-*` 字典序排在
`sse-interface` **之前** → `names[0]` 变成在线快照 → **`local` 模式选中了运行时产物**。

这是个真实 bug 而不只是测试问题：**用户明明选了离线，却吃到了"取决于抓取时刻"的结果**。
已修（`select_snapshot` 分离 `live-*`）并**固化成显式用例** ——
它是被一个不相干的降级测试意外撞出来的，不固化就会等它再自然暴露一次。

## 6. 剩余边界（如实记录）

1. **在线检索不覆盖 arXiv**：现有源是 Crossref + OpenAlex（需求 §4.3 的"文献数据源"未点名 arXiv API）。
   `lit_source=arxiv` 这个名字来自需求字段，实际走的是通用在线抓取路径——**命名与实现不完全对齐**，
   已在README §5.8 说明。改名字段会破坏 API 契约，故保留原名。
2. **在线快照不入库**：`live-*.json` 带时间戳，入库必脏，已 `.gitignore`。
   离线冻结的 `sse-interface.json` 照常入库。
3. **`materials` 仍未实现**：本次只做到"入口诚实拒绝"，算子是后续工作。
4. **`spawn` 方法名仍有误导**（`execution.ts`）：它不spawn 进程，只发指令。改名约 10 分钟，本次未做。
