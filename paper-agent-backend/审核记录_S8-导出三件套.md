## 2. 关键决策：session 导出必须走 AGH 原生

先核对了 AGH daemon 的 RPC 面。注册的方法只有：

```
authenticate / initialize / session/cancel / session/load / session/new / session/prompt
```

**没有导出 RPC**。所以 `kind=session` 唯一合规路径是调 AGH 原生 CLI（`agh.sh export <id> --format agnes|sharegpt|claude-code`）。

实测行为（`bash agh.sh`）：

| 场景 | 结果 |
| --- | --- |
| `--format agnes` 存在的会话 | 79 行 JSONL，退出码 0 |
| `--format sharegpt` | 2314 字节 JSON，退出码 0 |
| 不存在的 session | 退出码 **1** + `CAPABILITY_DENIED (-32006)`，**不产文件** |

→ 因此**失败路径天然可辨**：CLI 非零退出且无产物，直接映射为 `500 EXPORT_ERROR`，**不可能误判为成功**。

E2E 中进一步断言「BFF 导出结果与 `agh.sh export` 直出**逐字节一致**」，以此证明是原生导出而非自造格式。

## 4. 本步发现并修复的缺陷

### 4.1 `session` 导出 100% 失败（严重，实现期自测抓出）

原实现：

```ts
try { await execFileAsync(...) }
catch { throw ... }
finally { rmSync(tmp, ...) }      // ← 先删目录

const body = readIfExists(outFile) // ← 再读文件，必然读不到
```

`finally` 先执行 `rmSync`，之后才读产物 → **所有 session 导出都会走进「未产出文件」分支**，接口 100% 返回 500。

这类错误单靠「读代码」看不出来（语法完全合法、类型检查通过），是本步 E2E 实测 `kind=session` 才暴露的。修法：**在 `try` 内成功后就地读回内容**，`finally` 只负责清理。

> 这也是为什么 E2E 必须真调 AGH CLI 而不是 mock：mock 掩盖了文件生命周期错误。

### 4.2 审计包「假校验」风险 → 反向验证

`verify.py` 只做正向断言（退出码 0）是不够的——恒返回 0 的脚本也能通过。故 E2E 增加**反向用例**：

```
篡改包内 ledger.jsonl → python verify.py --run-dir ... → 退出码必须为 1
```

实测通过。这条断言把「校验脚本是否真的在校验」变成了可观测事实，而非声明。

`verify.py` 只 `import hashlib/json/sys/pathlib`，**不 import 本项目任何模块**（单测用正则断言了这一点）——校验必须独立于被校验方的代码，否则改代码就能改结论。

### 4.3 ZIP 实现：`unzip -t` 独立交叉验证

项目依赖只有 `typescript/tsx/vitest/@types`，无 ZIP 库，故自写 `export/zip.ts`（local header `0x04034b50` + data + central directory `0x02014b50` + EOCD `0x06054b50`，CRC-32 多项式 `0xedb88320`，deflate(8)/store(0)，UTF-8 flag `0x0800`，不支持 Zip64）。

**自写解析器自己校验自己不算数**，故：

- 单测：CRC-32 对 4 个标准向量（空串 / `"a"` / `"123456789"` / 狐狸句）逐值比对；中文文件名 + 嵌套目录 + store/deflate 两种方式回读；
- E2E：用系统 `unzip -t` 交叉验证 → `No errors detected`，并用 `unzip -q` 解压后逐文件重算 sha256。

顺带一个有用的性质：**固定 mod time/date ⇒ 同输入两次构建逐字节相同**，审计包因此可复现（单测有专门断言）。

### 4.4 未使用的 `sha256()` 辅助函数

`sha256(text: string)` 在 `service.ts` 中定义但无调用点（实际用的是 `createHash('sha256').update(buf)` 内联版本）。已删除。

## 5. 环境陷阱：Node 版本伪装成「AGH 集成坏了」

跑全量 `vitest` 时出现 1 个失败：

```
ConfigurationError: CONFIG_CREDENTIAL_STORE
  at resolveDaemonScope (packages/daemon/src/supervisor/scope.ts:214)
```

先用 `git stash push -u` 在改动前的 HEAD 上复跑同一用例 → **同样失败**，确认与 M7 无关。但不能就这么记为「既有失败」——顺手查清了根因：

```
本机裸 `node`               → v22.22.2（WorkBuddy 托管，排在 PATH 前面）
AGH 原生模块                 → agnes-system.node（只按 Node 24 的 libuv ABI 构建）
require('…/agnes-system.node') → "Rebuild Windows native artifact for the current Node.js/libuv runtime"
   ↓
windowsPrivateFilesAvailable() === false
   ↓
credentialFileEnforcement() 返回 level:'unavailable'
   ↓
credentialStore.read() 抛错 → ConfigurationError('CONFIG_CREDENTIAL_STORE')
```

用系统 Node 24 跑同一用例 → **通过**。全量 `vitest` 在 Node 24 下 **71/71 全绿**。

这个误报很有欺骗性：报错指向 AGH 配置与凭据，实际是运行时 ABI 不匹配。故新增 `scripts/quality-gate.sh` 固化三条：

1. 显式挑选 Node ≥ 24.10（不信任裸 `node`），找不到就 FATAL 退出而非静默跑出错结果；
2. BFF 单测 + 内核单测（连跑两次查抖动）+ `tsc` 三合一；
3. 脚本头部注释写清这条因果链，避免后人「修 AGH 源码」——**AGH 是只读引用，不得修改**。

## 7. 本步明确的边界（如实记录，不掩盖）

1. **审计包 `generated_at` 是真实导出时间**，故审计包**不是逐字节可复现**的（文件内容与哈希各自可复现）。
   这是审计要求（记录真实发生时间）与可复现要求的固有张力，正确做法是引入 `SOURCE_DATE_EPOCH` 式冻结参数，
   而不是把时间戳从清单里剔除。
2. **`events.json` 是从账本与任务状态重建的事件视图**，不是原始 SSE 流。SSE 总线缓冲是内存态、不持久化，
   故如实标注来源与局限，并指向 `kind=session` 取原始轨迹。
3. **`state.json` / `review.json` 若本次 run 未产出则不进包**（不塞空文件充数），`contents` 头如实反映实际内容。
4. **ZIP 不支持 Zip64**：单个文件 >4GB 或包内 >65535 项会失败。当前产物量级（数十 KB ~ 数 MB）远低于该限制，
   未实现超限降级。
5. **`session` 导出依赖 AGH daemon 在线**；daemon 不可用时如实 500 并给重试命令，**不降级为占位内容**。
